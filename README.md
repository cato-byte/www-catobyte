# catobyte.co

Personal portfolio and blog of a data engineer: projects, case studies and writing in English, Spanish and French.

The site is static HTML generated by a small Python package (`sitegen`) from Markdown and Jinja templates, then served from Amazon S3 through CloudFront.

## Quick start

```bash
./setup_venv.sh                                  # creates kunturvenv/ with build + test deps
./kunturvenv/bin/python -m sitegen serve         # build and preview on http://localhost:8000/en/index.html
./kunturvenv/bin/pytest                          # build the site and run all checks
```

## Layout

| Path | What it is |
|---|---|
| `site.yaml` | Name, photo, contact links, certifications, skills, experience |
| `content/projects/<lang>/<slug>.md` | Project case studies (YAML front matter + Markdown) |
| `content/projects/data/<slug>/*.csv` | Optional exported results (gold tables) rendered on the project page |
| `content/blog/<lang>/<post_id>.md` | Blog posts |
| `metadata/posts_metadata.json` | Registry of published posts and their dates |
| `templates/*.html` | Jinja templates (`base.html` is the shared layout) |
| `templates/i18n/<lang>.json` | All interface text, per language |
| `css/`, `js/`, `images/` | Static assets, copied as-is |
| `sitegen/` | The generator |
| `tests/` | Unit tests and checks on the built site |
| `dist/` | Build output (not committed) |

## Common tasks

**Add a project.** Create `content/projects/en/<slug>.md` (plus `es/` and `fr/` versions) with this front matter:

```yaml
---
title: Project title
summary: One sentence for cards and search results.
started: 2026-07          # optional
updated: 2026-10-12       # projects are sorted by this; the newest 3 appear on the home page
status: in_progress       # or completed
stack: [PySpark, Databricks]
cover: images/projects/<slug>.png   # optional, 1200x630
repo: https://github.com/...        # optional
demo: null                          # optional
---
```

**Show gold-table results on a project page.** Export a small CSV from Databricks into `content/projects/data/<slug>/` and reference it in the Markdown:

```markdown
<!-- bars: companies_by_country.csv -->      first column = label, second = value; header row = chart title
<!-- table: fact_sample.csv -->              any CSV, rendered as a table
```

Until the file exists the marker renders nothing, so the page never shows a broken block. For example, in a Databricks notebook:

```python
(spark.read.format("delta").load(GOLD + "dim_companies/")
    .groupBy("source_country").count()
    .withColumnRenamed("count", "Companies per country")
    .orderBy("Companies per country", ascending=False)
    .toPandas().to_csv("companies_by_country.csv", index=False))
```

**Write a blog post.** Add `content/blog/<lang>/<post_id>.md`. It stays a draft (listed by `python -m sitegen drafts`) until you publish it:

```bash
./kunturvenv/bin/python -m sitegen publish <post_id>   # registers it with today's date
```

Post conventions: the first `##` heading is the title, `##### Published on {{PUBLISH_DATE}}` is replaced by the date, and the image after `<!-- TITLE_IMAGE -->` is the cover.

**Change text.** Interface text lives in `templates/i18n/*.json`. The build uses strict undefined variables and a test checks that the three files have the same keys, so a missing translation fails the build instead of shipping a blank.

**Regenerate share images** (after changing your name in `site.yaml`): `./kunturvenv/bin/python scripts/make_share_images.py`.

## Deploy

Pushing to `master` runs the tests and deploys to S3 + CloudFront through GitHub Actions (OIDC, no stored AWS keys). Pull requests only run the tests. One-time AWS and GitHub setup, plus the manual fallback (`scripts/deploy.sh`), is described in [infra/README.md](infra/README.md).

## Quality checks

`pytest` builds the full site and fails if:

- any internal link, image, stylesheet or script points to a missing file, or an in-page `#anchor` has no target
- a page lacks `<!doctype>`, `lang`, `<title>`, viewport meta, description or canonical link, or doesn't have exactly one `<h1>` and one `<main>`
- an image has no `alt` attribute, or template syntax leaks into the output
- translations differ in keys, or `hreflang` / sitemap / redirect targets don't exist
- the newest project isn't on the home page, or a page lacks the Projects link

The same checks run on every push and pull request through GitHub Actions (`.github/workflows/ci.yml`).
